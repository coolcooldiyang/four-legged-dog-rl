## 4. 主训练曲线（`Oct02_19-08-27_`）

| 迭代 | mean_reward | episode_len | value_loss | surrogate | noise_std |
| --- | --- | --- | --- | --- | --- |
| 0 | -0.84 | 14.2 | 0.243 | 0.004 | 0.995 |
| **500** | **20.56** | 1225.0 | 0.004 | -0.006 | 0.353 |
| 1000 | 19.70 | 1191.7 | 0.005 | -0.006 | 0.387 |
| 2000 | 21.01 | 1198.7 | 0.005 | -0.007 | 0.395 |
| 3000 | 21.89 | 1223.8 | 0.006 | -0.006 | 0.383 |
| 4000 | 20.41 | 1231.0 | 0.004 | -0.008 | 0.384 |
| 5000 | 21.00 | 1219.8 | 0.005 | -0.008 | 0.377 |
| 6000 | 21.59 | 1230.5 | 0.006 | -0.003 | 0.388 |
| 7000 | 21.72 | 1235.1 | 0.006 | -0.006 | 0.378 |
| 8000 | 22.12 | 1216.5 | 0.006 | -0.005 | 0.376 |
| **8824（末）** | **22.69** | 1237.4 | — | — | ~0.373 |

**读法**：

- **500 迭代就跳变到 20.5** —— 从"完全不会站"到"能走完 25 秒"
- episode_len 从 14 步 → **1237 步**（上限 1250），说明**几乎不再摔倒**
- `noise_std` 0.995 → **0.373** 就停了，探索度收敛
- `value_loss` 稳定在 **0.005 量级**，没有发散

### 学习率是振荡的，不是衰减完

```
iter    0: 4.44e-4      iter 4000: 1.14e-4
iter  500: 3.90e-4      iter 5500: 1.00e-5
iter 1500: 5.85e-4      iter 6500: 5.77e-4
iter 3500: 5.77e-4      iter 8500: 1.00e-5
最低 1.00e-5  最高 1.00e-2
```
`schedule: adaptive` 按 KL 自动升降学习率（目标 KL=0.01），**在 1e-5 ~ 1e-2 之间来回跳是正常行为**，不是异常。

## 8. 关键发现（4 条）

### ① 训练饱和极早
reward 在 **500 迭代（约 9 分钟）** 就到 20.5，8000 迭代后只到 22.7。
**继续单纯加迭代的边际收益很低**，需要改奖励/课程/初始化才有突破。

### ② 上楼梯是明显短板
`stairs_up` 等级 **1.04**，其它地形 4~5。如果实机要上下台阶，这是首先要补的。

### ③ 指令范围从未扩展
`max_command_x` 全程 0.5，最快的课程扩张（iter 20000）没跑到。
**策略只见过基础速度指令**，超出范围的行为没有保证。

### ④ 没有跑完配置的 150000 迭代
配置 `max_iterations: 150000`，实际 **8824**（**5.9%**）。

## 11. ⚠️ 已知问题

### ① checkpoint 里的 `iter` 恒为 0

`model_8500.pt` 名叫 8500，但**内部的 `iter` 字段是 0**。

```python
# rsl_rl/rsl_rl/runners/on_policy_runner.py:320
self.current_learning_iteration = loaded_dict['iter']    # ← 拿到 0
```
```python
# train.py:14
env.common_step_counter = runner.current_learning_iteration * env.num_steps_per_env  # ← 0
```

**后果**：

- 权重和优化器正常恢复 ✓
- 但迭代计数归零 → **课程表从头开始** ✗
- TensorBoard 曲线的横轴也从头计（所以备份里每个续训 run 都是 0→N）

**对本次 checkpoint 恰好无害**：指令范围课程在 **iter 20000** 才第一次扩张，而 8500 < 20000，
本来就该在基础范围。**但从 >20000 的 checkpoint 续训就会倒退。**

### ② 续训不会覆盖旧 checkpoint

每次续训会**新建带时间戳的 run 目录**（备份里那 4 个短 run 就是证据），
所以 `Oct02_19-08-27_` 里的 18 个 checkpoint 是安全的。

### ③ `max_command_x` 语义

日志里 `max_command_x` 显示 0.5，但配置的基础范围是 `vx ±1.0`。
这是**课程用的当前上限**（`command_ranges["lin_vel_x"][1]`），不是配置原始值。
只训到 8824 → 从未被扩张。

## 12. 若要继续训，建议

| 优先级 | 动作 | 理由 |
| --- | --- | --- |
| 高 | 跑到 **iter 20000** 让指令范围扩张 | 当前只训过基础速度 |
| 高 | 检查 `stairs_up` 落后的原因 | 等级 1.04 vs 其它 4~5 |
| 中 | 考虑**提高奖励上限**（速度跟踪权重 / 更难的指令） | reward 500 迭代就饱和 |
| 中 | 从 `model_8500` 续训时**新建 run 目录** | 避免和旧曲线混淆 |
| 低 | 跑满 150000 迭代 | 边际收益低，本次 5.9% 就到 22.7 |
